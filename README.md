# AI test · 扩图效果对比

把一张原图和多个模型的扩图结果放在一起直观比对，边看边打分，自动出模型排行。

技术栈：React 18 + TypeScript + Vite + CSS Modules。

## 跑起来

```bash
cd Web/AITest
npm install
npm run dev        # http://localhost:5180
npm run build      # 产物在 dist/，base 是相对路径，可直接丢 OSS / GitHub Pages
```

## 当前数据

59 个用例，5 个模型列，90 张结果图。`public/data/` 约 135MB，在 `.gitignore` 里，不进版本库。

| 批次 | 模型列 | 用例 | 扩图规格 |
|------|--------|------|----------|
| `out_20261118_174209` | 火山 | 50 组（动漫/动物/风景/静物/人像 各 10） | 1080×2560 → 1512×2992，四周各 216px |
| `扩图测试结果` | 阿里 A居中等比 | 10 组 | 1080×2560 → 928×2224，原图居中占 50% |
| | 阿里 B上下扩图 | 10 组 | → 656×3136，满宽，上下各扩 |
| | 阿里 C左右扩图 | 10 组 | → 1312×1568，满高，左右各扩 |
| | 阿里 D非居中扩图 | 10 组 | → 800×2576，原图靠右，左侧扩 |

两批只有 **动物 / 影像杂志02-26** 这一张原图是同一张（已自动合并成一个用例，能看到 5 个模型并排），
其余互不重合，所以跨厂商同图对比目前只有这一组。

两批的像素账本差别很大，是评测时要先知道的事：

| 模型 | 原图内容被缩放到 | 输出画布面积 | 原图区域保留的像素 |
|------|------------------|--------------|--------------------|
| 火山 | 100% | 1.64x | 100% |
| 阿里 A居中等比 | 43.2% | 0.75x | 18.7% |
| 阿里 B上下扩图 | 60.6% | 0.74x | 36.8% |
| 阿里 C左右扩图 | 61.1% | 0.74x | 37.3% |
| 阿里 D非居中扩图 | 49.6% | 0.75x | 24.6% |

火山是在原图外面补画布，原图像素一个不动；阿里是整体重采样，输出画布比原图还小，
原图那块只剩 19%~37% 的像素。切到「原图区域」对齐一眼就能看出来。

结果图统一转成 WebP q95（像素尺寸不变），原图保持上游原样。

## 四种加载数据的方式

| 方式 | 怎么做 | 适合 |
|------|--------|------|
| 批量产出目录 | `python3 scripts/import_batch.py --src <目录> --model 模型名` | 火山这类批跑脚本的输出，一行命令入库 |
| 清单 | 图片放进 `public/data/cases/`，`npm run manifest`，再点「重载清单」 | 自己攒的评测集 |
| 本地文件夹 | 拖文件夹进窗口，或点「导入文件夹」 | 临时看一批图，不落盘 |
| 示例数据 | 点「载入示例」，图片由 canvas 现场生成 | 先熟悉界面 |

### 导入批量产出

`scripts/import_batch.py` 自动识别两种目录结构：

**A）一对一** —— 一个模型一列（火山批跑脚本的输出）

```
out_20261118_174209/
  01_原图/001_动漫_原图.jpg
  02_扩图结果/001_动漫_扩图.png
  03_对比图/...          ← 跳过
  result.json            ← 分类、原图名、尺寸都从这儿读
```

```bash
python3 scripts/import_batch.py --src ~/Desktop/out_20261118_174209 --model 火山
```

**B）多场景** —— 每个场景目录单独成一列（阿里 wanx2.1 的输出）

```
扩图测试结果/
  原图/人像/影像杂志02-124.jpg
  A_居中等比/01_A_center_人像_影像杂志02-124.png
  B_上下扩图/...  C_左右扩图/...  D_非居中扩图/...
```

```bash
python3 scripts/import_batch.py --src ~/Desktop/扩图测试结果 \
        --model 阿里 --model-id wanx2.1 --align detect
```

场景目录名就是列名（`A_居中等比` → `阿里 A居中等比`），`--model` 要短，
否则右栏打分和排行榜的名字列放不下。

**同一张原图在不同批次里会自动合并成同一个用例**（按「分类 + 原图文件名」认亲），
所以同图跨模型可以直接并排看。常用参数：

```
--align auto|detect|centered|none   原图位置怎么定，默认 auto
--encode webp|jpeg|none             结果图转码，默认 webp q95；none 为原样拷贝
--quality 95                        转码质量
--limit 3                           只导前 3 条，先试水
--layout auto|pairs|variants        结构识别错了可以强制指定
--model-id / --note                 模型 id 与备注（备注显示在悬浮提示里）
```

### frame 是怎么定出来的

`frame` 决定「原图区域」对齐准不准，`--align` 有四档：

- `auto`（默认）结果比原图大 → 按「原图按原始像素居中粘贴」直接算，零成本且精确（火山这类）
- `detect` 跑像素检测：多尺度归一化互相关，把原图在结果里的缩放比和位移找出来。
  重采样过的、不居中的都能找准（阿里 D 非居中那种），每张约 1 秒，会打印匹配得分
- `centered` 只按居中推算
- `none` 不写，交给前端自动猜 + 左栏滑块手动修正

检测器也能单独跑来验证某一对图：

```bash
python3 scripts/detect_frame.py 原图.jpg 结果.png
# frame = [0.330078, 0.253487, 0.669, 0.49237]
# score = 0.9863      ← 1.0 为完全一致，低于 0.75 会提示人工确认
```

阿里这 40 张的检测得分在 0.88~0.998，且每个场景内 10 张独立检测出来的 frame
几乎完全一致（互为交叉验证）。

目录约定：

```
public/data/cases/
  001-人像左右扩/
    original.jpg      ← 原图，也认 原图 / input / src / source / raw
    seedream.jpg      ← 文件名即模型名
    nano-banana.jpg
    qwen-image.jpg
  002-风景上下扩/
    ...
```

生成清单：

```bash
npm run manifest                              # 等价于 python3 scripts/gen_manifest.py
python3 scripts/gen_manifest.py --frame auto  # 顺便写入 frame，需要 Pillow
```

`public/data/manifest.example.json` 是手写清单的参考格式（模型显示名、备注、标签都能在这里定）。

URL 参数可以预设打开方式，方便把某种对比姿势发给别人：

```
?demo=1                  打开即载入示例
?view=slider | flip      默认视图
?align=frame             默认按原图区域对齐
?case=018_动物           直接定位到某个用例（用例 id 或原图文件名）
```

## 三种对比视图

- **网格对比**：原图和所有模型并排，缩放平移全部同步，适合扫整体构图
- **滑块对比**：两张图叠放，拖中间竖线拉幕，适合盯接缝
- **闪视对比**：两张图完全重合，按住空格切换，细微差异一闪就看出来

## 关键概念：原图区域对齐

扩图结果比原图大，直接并排看，同一处内容在两张图里的位置、大小都不一样，没法比。

左栏「对齐方式」选 **原图区域**，程序会把每张结果图里**原图那一块**对到屏幕同一位置、同一尺寸。
这时候缩放平移同步，像素级差异直接可比：原图区域有没有被模型改动、接缝在哪、纹理有没有接上，一眼可见。

原图在结果里的位置来自：

1. 清单里显式写的 `frame: [x, y, w, h]`（0~1 比例，最准）
2. 没写时按「原图按原始像素居中粘贴进大画布」自动推算
3. 推算不准时，用左栏「原图占比修正」滑块手动校正

勾上「标出原图边界」会在每张结果图上画出这块区域的虚线框。

## 用例多了怎么翻

左栏顶部有分类筛选（取用例的第一个标签），选中后 `←` `→` 和页码都只在这个分类里走，
适合「先把 10 组人像连着看完」这种评测节奏。列表小图是导入时生成的 `_thumb.webp`，
不会去拉 2MB 的原图。下划线开头的文件都是工具自己生成的，不会被当成模型结果。

## 打分与导出

每张结果图下方和右栏都能打 1~5 分，并给本用例选一个「最佳」。
评分存在浏览器 localStorage，刷新不丢；右栏「模型排行」按均分排序，可导出 CSV / JSON。

## 怎么给别人看（当前方案：内网直开，不发公网）

素材是内部影像库原图 + 厂商横评结果，不往公网放。服务已监听所有网卡，
同事在公司网里直接开你的内网地址即可，不需要构建也不需要部署。

```bash
npm run dev
#   Local:   http://localhost:5180/
#   Network: http://10.220.174.135:5180/   ← 把这行发出去
```

建议连参数一起发，对方打开就是最能说明问题的视角：

```
http://<内网IP>:5180/?align=frame              原图区域对齐
http://<内网IP>:5180/?case=018_动物&align=frame  唯一两家都跑过的那组，五列并排
```

三点要知道的：

- **IP 会变**。换 Wi-Fi、插网线、连 VPN 之后内网地址都会变，重新跑一下
  `ipconfig getifaddr en0` 看当前地址。
- **进程要留着**。在自己的终端里跑 `npm run dev` 并保持窗口不关；
  关了终端或合盖休眠，别人就打不开了。
- **评分是各人各自存的**。打分写在各自浏览器的 localStorage 里，不互通。
  要汇总就各人点「导出 CSV」，拿到一起比。

如果同事连不上，依次查：你的 `npm run dev` 还在跑吗 → 对方和你在同一网段吗
→ 系统设置里的防火墙是不是开了（开了要允许 node 接受传入连接；当前这台是关着的）。

## 以后要发公网的话

`.github/workflows/deploy.yml` 已经按另外两个项目的套路写好了（push main → Actions
构建 → Pages 发布，产物目录是 Vite 的 `dist`）。构建产物用相对路径（`base: './'`），
丢到任何子目录都能跑，不用像 Next 那两个项目配 `basePath`。

```bash
npm run build      # 产物在 dist/，含 public/data 里的全部图片
npx vite preview   # 本地验证产物
```

真要发之前得先处理两件事：

1. **图片默认不入库**。`.gitignore` 忽略了 `public/data/cases/` 和 `manifest.json`，
   不删这两行推上去，站点是空的。而 134MB 二进制一旦进了 git 历史就很难干净摘掉。
2. **先瘦身**：

   ```bash
   python3 scripts/slim_data.py --dry-run     # 看能省多少
   python3 scripts/slim_data.py               # 原图转同尺寸 WebP q90：94MB → 16MB
   python3 scripts/slim_data.py --results     # 连结果图一起压：134MB → 43MB
   ```

3. GitHub Pages 免费账号的站点是公网可见、会被搜索引擎收录的。内部素材要上线，
   优先考虑阿里云 OSS 私有桶之类能控制权限的地方。

## 目录结构

```
src/
├── components/   ← 界面组件（视图、面板、弹窗）
├── hooks/        ← 状态与手势（useCompareState 是核心）
├── utils/        ← 对齐数学、清单解析、文件夹导入、示例数据、导出
├── types/        ← 类型定义
└── styles/       ← 全局样式与共享原子类
scripts/
├── import_batch.py   ← 导入批跑产出并合并 manifest（认两种目录结构）
├── detect_frame.py   ← 像素检测原图在结果里的缩放与位移
└── gen_manifest.py   ← 扫描已有 cases 目录生成 manifest
```

核心逻辑在 `src/utils/frame.ts`：把"原图区域"矩形铺满视口，再叠加共享的 zoom / pan，
不同尺寸的图片因此能严格对齐。
